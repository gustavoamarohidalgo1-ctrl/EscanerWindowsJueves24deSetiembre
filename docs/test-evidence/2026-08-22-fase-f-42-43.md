## Cierres aplicados

1. La retención dejó de ser una preferencia diferida: una política potencialmente destructiva pide
   confirmación, persiste la decisión, registra primero la purga remota cuando corresponde y ejecuta
   una pasada inmediata. Los hooks tras OCR y tras confirmar usan la misma semántica segura.
2. El barrido cubre borradores con OCR realmente publicado y, al borrar manualmente, borradores y
   compras terminales de todos los negocios del dispositivo. Un fallback manual sin snapshot OCR
   no se confunde con OCR completado. Fallos de purga o filesystem conservan el archivo y se
   reportan; no se afirma un ACK cloud por tener solo una intención durable.
3. `RetainedImageCipher` autentica versión, nonce, longitud y tag AES-GCM; un prefijo `FSE1` aislado
   o un envelope corrupto no se acepta ni se sobrescribe. La UI consume bytes descifrados en memoria
   y no crea un JPEG temporal en claro.
4. La exportación se renombró y versionó como `ACCOUNTING_LEDGER`, `schemaVersion = 3`. Incluye
   negocio, catálogos, alias, compras/líneas, balances, movimientos y auditoría completa del negocio,
   también eventos sin compra. Exporta metadatos de imagen, nunca bytes o rutas internas, y excluye
   borradores/OCR, cuenta, preferencias, transporte, caché, credenciales y tokens. Dos lecturas
   distintas hacen fallar cerrado la instantánea; el destino SAF se trunca/elimina si puede y, si
   el proveedor no permite confirmar la limpieza, la UI advierte que puede quedar contenido parcial.
5. Respaldo comercial y documental son opt-ins separados y apagados por defecto. Desactivar el
   respaldo comercial cancela trabajo normal, pero conserva el canal mínimo de tombstones de purga;
   no se presenta como borrado remoto. Las imágenes solo se transfieren con ambos opt-ins, como JPEG
   derivado por HTTPS; Firebase Storage cifra de forma administrada en reposo, no E2E.
6. `deleteMyAccount` solicita la contraseña solo para `reauthenticate`, la descarta y fuerza un ID
   token nuevo. Functions exige `auth_time` no mayor de cinco minutos antes de cualquier mutación;
   refrescar un token antiguo no satisface el control.
7. El flavor `cloud` incluye Crashlytics, pero fuerza colección automática a `false`, no registra
   excepciones manuales ni sube mapping. El opt-out descarta reportes no enviados si Firebase ya
   estaba inicializado. Analytics sigue separado, apagado por defecto y limitado a eventos/atributos
   cerrados sin RUC, nombres, direcciones, productos, importes, OCR, rutas, tokens ni motivos libres.
8. Release ejecuta R8 y resource shrinking en ambos flavors con reglas mantenidas para Room,
   WorkManager y enums persistidos. El bloqueo opcional se lanza solo con la Activity reanudada,
   admite biometría fuerte o PIN/patrón/contraseña del dispositivo y se desactiva de forma
   recuperable si el dispositivo deja de ofrecerlos.
9. Una operación documental legacy que pudo salir sin un tenant fijado ya no permite adivinar el
   destino. Room devuelve `LEGACY_DESTINATION_UNKNOWN`, conserva/cifra la última fuente local y la
   UI exige revisión manual. Solo una fila sin intento demostrable se resuelve como
   `NOT_REQUIRED`; las purgas nuevas quedan fijadas al binding exacto.
10. Cuando `SYNC_DOCUMENT_PURGE` queda durable, el derivado AES-GCM `.fse` se elimina y verifica
    localmente sin esperar red. Un fallo devuelve `DURABLE_ARTIFACT_RETRY_REQUIRED`: conserva la
    señal, despierta el canal de purga y permite que el barrido/reinicio reintente. El mantenimiento
    elimina además derivados huérfanos, manteniendo solo IDs de uploads Room todavía abiertos.
11. La preparación documental limita el archivo fuente antes de reservar bytes y calcula
    `inSampleSize` por píxeles decodificados: una fuente válida de 8.000×8.000 se decodifica a un
    máximo de 4 millones de píxeles, no a un bitmap ARGB de ~256 MiB. Un `OutOfMemoryError` se
    traduce al error permanente cerrado `DOCUMENT_PREPARATION_RESOURCE_LIMIT`. El fallback remoto
    relee sesión, binding, ambos opt-ins e `isBackedUp` justo antes de cada I/O y antes de entregar
    bytes; una revocación durante la suspensión sanea el buffer.
